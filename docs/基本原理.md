# 凭据登录

我们认为，一个由正常玩家发起的传入连接必然会包含一些独一无二的元信息，基本上可能包含以下内容：
- 仅与连接相关的信息：
  - IP
  - 提供的名字
  - 提供的UUID
- 提供的凭据：
  - Yggdrasil 登录凭据
  - floodgate 登录密钥

这一类信息直接在传入连接中可以获得，所以我们可以将其作为会话凭据，然后将会话凭据关联到唯一的玩家档案。

## 会话凭据获取

从目前的元信息中我们将能获取到一个会话凭据。

### Yggdrasil 凭据登录

常规来说，服务器只会使用 Yggdrasil 登录凭据来确定唯一的玩家，并使用对应于玩家UUID的玩家档案，这是正版登录或者使用自定义 Yggdrasil 验证服务器的做法。

我们可以将一组已经验证过的 Yggdrasil 凭据所对应的 UUID 作为我们需要的会话凭据。

### floodgate 密钥登录

在有 floodgate 参与之后，floodgate 还会验证连接中包含的 floodgate 登录密钥，然后从连接带有的 xuid 获取相对应的信息，并最终映射到某个 00000000 UUID 或者某个正版账户的 UUID 上，并对应于一个玩家档案。

我们可以将一组已经验证过的 带有 floodgate 密钥 的 xuid 作为我们需要的会话凭据。与此同时，我们只是简单地忽略了 floodgate 提供的 UUID。

### 基于连接特征的凭据登录

我们可以将`仅与连接相关的信息`绑定到一个短期的`登录凭据`上。

登录凭据将会包含：
- IP
- 提供的名字
- 提供的UUID
- 关联的会话凭据

登录凭据获取流程：
- 玩家先行进入服务器
- 使用自定义命令完成登录认证
- 生成会话凭据，随后生成登录凭据。
- 将玩家踢出服务器

在第二次连接时，`仅与连接相关的信息`就能够对应到一个登录凭据上。

我们会使用这一组登录凭据中包含的 关联的会话凭据 作为我们需要的会话凭据。
